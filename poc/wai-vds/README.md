# OpenStrudel → WAI VDS: проверка подключения

Проверено 5 октября 2026 года на Mac Mini. Адаптер подготовлен в отдельном PoC и не входит в опубликованные Mac/iOS-приложения или Home. DigitalOcean остаётся существующим облачным способом в приложении.

## Что работает

`client.mjs` использует фактический WAI VDS API v1. Он принимает только выделенный `wai_test_` ключ, перед каждой записью проверяет, что инфраструктура и платежи эмулируются, и использует только `/agent/servers` для выдачи. Реального checkout, списания или создания платной VM в клиенте нет.

Перед первым запросом `smoke.mjs` сохраняет номер попытки в приватный журнал. При потере ответа повторный запуск с той же папкой повторяет тот же номер. Запрос статуса читает существующий заказ; удаление сверяет исходный номер попытки и связь заказа с сервером. Запрос, присоединённый сервисом к чужой незавершённой попытке, не принимается как собственный объект для удаления.

В API v1 состояние `ready` от WAI VDS означает подготовленную VM с SSH и Docker. Оно никогда не переводит OpenStrudel в готовность и не открывает вход OpenAI. У эмулятора отдельное состояние `sandboxReady`; учебный IP не используется для подключения. Ошибка доступа WAI VDS отличается от недоступности сети и от авторизации OpenAI на Home.

Тестовый ключ остаётся в существующем приватном файле рабочей папки OpenStrudel. Он не копируется в исходники, журнал попытки, отчёт или нативное приложение. Клиент не скачивает root-ключ и не читает авторизацию Codex.

## Проверка

```sh
node --test poc/wai-vds/*.test.mjs poc/cloud-onboarding/*.test.mjs poc/eqvps/provider.test.mjs
node poc/cloud-onboarding/preflight.mjs --base-url https://server.waiwai.is
node poc/wai-vds/production-readiness.mjs \
  --env-file '/Users/mikwiseman/Library/Application Support/OpenStrudel/runtime/.data/workspace/personal/integrations/wai-vds/.env.production'
node poc/wai-vds/smoke.mjs \
  --env-file '/Users/mikwiseman/Library/Application Support/OpenStrudel/runtime/.data/workspace/personal/integrations/wai-vds/.env' \
  --evidence-dir .data/wai-vds-readiness/2026-10-05
```

Повторный запуск с завершённым журналом проверяет его результат без новой выдачи. Новую папку используйте только для намеренно нового учебного испытания. При прерывании сохраните `trial.json` и повторите ту же команду. Если сервис вернул `unknown`/`attention`, требуется сверка текущей операции; новый сервер автоматически не заказывается. При смене режима или отзыве ключа проверка останавливается.

Доступ к эмулятору ограничен сроком и квотой; его продолжение не означает разрешение на платное испытание. Скрипт использует уже работающий API, не запускает службу, Home или расписания.

## Обновление WAI VDS v4: отдельный живой пилот

5 октября прочитаны новые результаты WAI VDS на commit `aead64306504c0d2b2cc0fed4c09dff316a0021b`. Пользователь отдельно разрешил одну VM в пределах $10 в чате WAI VDS. Согласно `outputs/live-pilot.json`, эта VM была создана в 10:07 UTC и удалена в 10:24 UTC; прежние 17 VM сохранились. Это разрешение использовано для того пилота и не переносится на новую VM OpenStrudel.

Пилот подтверждает выдачу Ubuntu 26.04.1 с 2 ГБ RAM / 20 ГБ диска, root/SSH по скачанному ключу, Docker, внешний HTTP, восстановление после reboot, выгрузку тестовых данных и удаление. Три шаблона применялись последовательно к одной VM. Входной платёж был подписанным тестовым событием; реальных платежей покупателя не было. Текущая строка usage около $0.00181 не является финальным счётом или доказанной полной стоимостью тарифа.

Поле `openStrudelClientRealServer` в этом протоколе означает проверку API status/access и загрузку SSH-ключа временным клиентом. Протокол не содержит установки Home, его TLS-идентичности, личного входа OpenAI на этой VM или подключения второго устройства. Перезапуск SSH/Docker/HTTP закрывает часть инфраструктурной проверки, но не проверку восстановления Home.

В v4 исправлена конфигурация SSH. API, схема авторизации, назначения и профиль каталога остались прежними, поэтому адаптер менять не потребовалось. После обновления выполнены только бесплатные чтения: наш ключ по-прежнему видит четыре удалённых учебных сервера и ноль активных; публичный checkout закрыт. Завершённая выдача в эмуляторе не повторялась. Новые протоколы и хеши прочитанных доказательств сохранены в `.data/wai-vds-readiness/2026-10-05-v4/`.

## Обновление WAI VDS v6: production-оплата и отдельный ключ

5 октября проверен релиз `20261005-vds-v6`, исходный commit `7ad0159c75a96f1af6d8d66491e35f8c57b0d853`. Публичный checkout открыт: $12 или 12 USDT за 30 дней для прежнего общего профиля 2 ГБ / 20 ГБ. По протоколу сервиса его стартовый предел — одна активная VM или резерв. Каталог не выдаёт свободную ёмкость, поэтому успешное чтение не доказывает наличие места для заказа.

Протоколы Stripe и Cryptomus подтверждают настоящие неоплаченные счета, их завершение и подписанные уведомления. Реальных списаний, криптопереводов и выплат продавцу не было. Новый production-ключ OpenStrudel ограничен отдельным аккаунтом, срок по документам до 4 ноября 2026. `GET /me` этим ключом подтверждён; заказов и серверов 0. Scope не даёт читать управление API-ключами. Исходный sandbox сохранён.

`production-readiness.mjs` выполняет только три фиксированных GET: health, каталог и собственный аккаунт. Credential передаётся только в `/api/v1/me`, только на закреплённый HTTPS origin; redirect запрещён. Ключ, email, CSRF, IP и данные root не входят в отчёт. Скрипт не имеет пути создания заказов, платёжных сессий или VM. Его тесты также проверяют, что `refunded`/`needs_refund` не приводят к повторной выдаче и что оставшееся после истечения счёта `order.status=checkout` не считается оплатой. USD и USDT сохраняют отдельные валюты и суммы.

Evidence: `.data/wai-vds-readiness/2026-10-05-v6/`. В этом прогоне 0 заказов, 0 новых VM и 0 списаний. Новый endpoint готов к ограниченному чтению; это не подтверждение полного сценария Home. 5 октября пользователь дополнительно поручил сделать оплату под брендом OpenStrudel без отдельного кабинета VDS. [Сценарий и контракт](../../docs/integrated-cloud-checkout.md) переданы в чат WAI VDS по его прямому разрешению; реализация там продолжается вместе с дизайном и выбором постоянного домена. Не направлять production-ключ на новый origin автоматически.

## Постоянный адрес, 5 октября

По решению пользователя сервис перенесён на `https://server.waiwai.is`, без совместимости с прежним `/vds`. Публичные `/healthz`, `/api/v1/catalog` и `/openapi.json` проверены на новом домене с обычной проверкой сертификата и явным разрешением IP `103.45.247.25`. OpenAPI объявляет этот же сервер. Публичный DNS через Google DNS-over-HTTPS возвращает `103.45.247.25`; системный resolver Mini и UDP-запросы пока сохраняют отрицательный ответ. Затем на том же домене бесплатно проверен `GET /api/v1/me` существующим отдельным ключом: заказов и серверов 0. Сертификат и имя проверены, redirect не используется. Обычное DNS-разрешение пока остаётся отдельной незавершённой проверкой. Закрытая конфигурация интеграции уже содержит новый адрес.

Read-only адаптер закреплён на новом origin и отклоняет старый адрес, HTTP, другие пути и redirect. Повторная выдача учебной VM не выполнялась. Оплата без отдельного кабинета VDS остаётся задачей Mac/web; iOS подключает уже готовую команду, см. [текущий сценарий](../../docs/ios-cloud-payments.md).

## Обновление WAI VDS v10: контракт Home и Mac-клиент

5 октября проверен опубликованный backend `998aad1`, релиз `20261005-vds-v10`, OpenAPI `2.0.0` на `https://server.waiwai.is/api/v2/openstrudel/openapi.json`. Теперь есть отдельный Home-профиль 4 ГБ / 30 ГБ / публичный IPv4, вход владельца PKCE, котировки, долговечные заказы, hosted checkout и claims подключения. Общий операторский API-ключ не используется для native API. Публичный каталог Home закрыт, розничной цены нет. $12 за общий тариф и $24 из учебных fixtures не являются ценой Home.

Системный DNS Mini теперь разрешает новый домен. Каталог и OpenAPI прочитаны через обычный HTTPS с проверкой имени и сертификата, без подстановки IP и redirect. В этом прогоне credentials на новый API не передавались. Старые sandbox-прогоны не повторялись.

В `native/OpenStrudel/Sources/WaiVDSContract.swift` и `WaiVDSClient.swift` подготовлена основа Mac-клиента: личный вход размещения, Keychain, сохранение запроса заказа до отправки, сверка оплаты, восстановление без повторной покупки и проверка TLS Home до отправки owner token. **К экрану покупки клиент ещё не подключён.** 27 новых и 49 прежних Mac-тестов прошли. Существующий DigitalOcean сохранён; на iOS нового пути покупки нет.

Полная граница реализации, тестов и оставшихся экранов/управления описана в [нативной интеграции v2](../../docs/wai-vds-native-integration.md). Новое evidence лежит в `.data/wai-vds-readiness/2026-10-05-v10/`; прежнее evidence v1 остаётся историческим. 250 тестов producer, его синтетический PKCE и бесплатное чтение профиля не являются настоящей приёмкой Home.

До публикации нужны законченные экраны и управление, утверждённая цена, новый конкретный бюджет и настоящая связка платёж → VM 4/30 → Home → личный OpenAI → второе устройство → SSH/TLS после reboot → экспорт/восстановление → отмена/удаление. Реальных новых VM и платежей в этом прогоне 0. Старые разрешения не применяются. Вопрос о прежнем блокере повторно не задавался.

Монитор готовности остаётся включён; курсор и последний результат сохраняются в `.data/wai-vds-readiness/state.json`. iOS 1.0 (12) проверяется Apple отдельно от приёмки нового способа покупки VDS.
