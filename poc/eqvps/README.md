# EQVPS: проверка интеграции OpenStrudel

Это изолированный PoC провайдерского API. Он не входит в Home runtime, не меняет опубликованную сборку и не создаёт серверы за деньги. Собственный сервис заказа и оплаты разрабатывается отдельно в чате «WAI VDS — сервер в один клик». Сначала нужно подтвердить провайдерский контракт, затем подключать готовый сервис к приложению.

## Запуск

Node.js 22.5+; дополнительных зависимостей нет.

```sh
node --test poc/eqvps/provider.test.mjs
node poc/eqvps/probe.mjs
```

Второй вызов делает настоящие бесплатные запросы к публичному каталогу и `tools/list` MCP. Результат включает дату, подходящие публичные тарифы и доступность партнёрских возможностей. Это не проверка платёжного процесса или реального сервера. Публичная цена не является оптовой котировкой, а наличие тарифа в каталоге не доказывает доступную мощность в регионе.

Когда оператор создаст партнёрский аккаунт и сохранит ключ `rk_…` в своём файле с правами `600` или `400`:

```sh
node poc/eqvps/probe.mjs --token-file /private/path/eqvps-token
```

Не сохраняйте ключ в репозитории, не передавайте его прямо в аргументах и не присылайте в чат. Проверка схемы не создаёт клиента, план, инвойс или VM.

Для **существующих тестовых** плана и клиента:

```sh
node poc/eqvps/probe.mjs --token-file /private/path/eqvps-token --dry-run --plan-id PLAN_ID --client-id CLIENT_ID
```

Сначала заново читается схема `reseller_order_for_client`. Вызов разрешён только при явно объявленном булевом параметре `test`, допускающем `true`. Затем отправляется ровно один запрос с `test: true`. Если провайдер не объявляет такую возможность, проверка останавливается. Платного варианта запроса и автоматического повтора нет. Полученный ответ означает лишь принятие RPC симуляции; реальный SSH, установка, перезагрузка и платёж остаются непроверенными. Содержимое ответа скрыто, потому что даже тестовый ответ может содержать пароль.

## Что подтверждено источниками

Проверено 4 октября 2026 года; условия могут меняться.

| Вопрос | Что известно | Следствие |
| --- | --- | --- |
| Модель продукта | [Partners](https://eqvps.com/en/partners): свой бренд, checkout, клиенты и выдача VM через партнёрский аккаунт | Клиент может не регистрироваться у провайдера. Баланс и ответственность перед провайдером принадлежат оператору. |
| Симуляция | [Reseller API](https://eqvps.com/en/docs/reseller): `test: true` возвращает макет, без VM и списания | Не выдавать результат симуляции за инфраструктурный acceptance. Проверять актуальную авторизованную схему перед запросом. |
| Адрес и порты | [Network](https://eqvps.com/en/docs/network): NAT ограничивает входящие подключения | Для прямого Home TLS нужен dedicated IPv4. Фильтр PoC также требует 4 GiB RAM, 30 GB диска и Ubuntu 24.04. |
| Карта | [Paying](https://eqvps.com/en/docs/paying): карта используется через покупку криптовалюты у стороннего сервиса | Это не готовый checkout дешёвого сервера для новичка. Собственную оплату нужно реализовать отдельно. |
| Продление | [Reseller API](https://eqvps.com/en/docs/reseller): автопродление включено по умолчанию | Перед живым заказом подтвердить управление продлением и согласие клиента. |
| Доступ | [Cabinet](https://eqvps.com/en/docs/cabinet): пароль выдаётся один раз | Секрет нужно безопасно доставить владельцу. Передача сервера в личный провайдерский аккаунт клиента не подтверждена. |
| Ответственность | [Terms](https://eqvps.com/en/terms): нет гарантии uptime; правила возврата предоплаты ограничены | До публичных продаж подтвердить юридическое лицо, резервное копирование, возвраты и договорные условия. |

Документация не подтверждает `user_data`/cloud-init, SSH-ключ и ключ идемпотентности именно для reseller-заказа. PoC проверяет объявленные поля схемы, но наличие поля само по себе не доказывает успешную установку. Документы также расходятся в описании писем клиенту; требуется проверка реальной настройки партнёрского аккаунта.

## Граница с отдельным VDS-сервисом

VDS-сервис владеет аккаунтами, платежами, долговечными заказами, сверкой неизвестных результатов и жизненным циклом VM. В нативных приложениях OpenStrudel не должно быть провайдерского ключа или логики списания.

OpenStrudel получает статус заказа и адрес готового Home, проверяет его TLS-идентичность и подключается по приглашению владельца. Учётная запись OpenAI авторизуется самим владельцем на основном сервере один раз. Подключённые устройства используют этот Home. Интеграцию нельзя объявлять готовой, пока нет проверенного пути установки Home и живого теста доступа после перезагрузки.

## Условия следующей проверки

1. Партнёрский аккаунт оператора, ключ и тестовые сущности; проверка авторизованной схемы и бесплатной симуляции.
2. Подтверждение оптовой цены, юридических условий, отмены и настроек продления.
3. Отдельный согласованный бюджет живого теста. Ранее использованное разрешение на временный DigitalOcean-сервер сюда не переносится.
4. Реальная выдача VM, безопасная установка, SSH/TLS, перезагрузка, повторное подключение и подтверждённое удаление тестовой VM.

Пока эти условия не выполнены, платная выдача и новая кнопка покупки в публичной сборке выключены.
