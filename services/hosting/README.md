# WAI VDS

Вход по email через Resend опубликован на server.waiwai.is. [Magic Link: поведение, безопасность и runbook](docs/MAGIC-LINK.md).

Самостоятельный сервис: аккаунт → назначение сервера → заказ → hosted checkout → проверенное платёжное событие → VM → SSH/root. Отдельный репозиторий, ветка `codex/vds-mvp`.

**Боевой сервис: https://server.waiwai.is/ · релиз `20261005-vds-v9`.** Stripe и Cryptomus работают через отдельную LIVE App WAI Pay. Стартовая цена: $12 картой или 12 USDT за 30 дней с момента готовности, продление вручную. Checkout открыт; начальный предел — одна активная VM или оплачиваемый резерв на весь сервис.

Перед оплатой резервируется место. Перед оплатой и созданием проверяется свежая публичная оценка Kamatera для точного профиля: сейчас $6 + 2% = $6.12 без подтверждённого налога, установлен предел этой оценки $10. Это не окончательный счёт провайдера. Неизвестная цена или результат создания останавливают новые операции; повторный POST не создаёт дубликат.

**213/213 тестов на Mac и Linux/Node 24, без пропусков.** Включены ежедневные age-копии данных сервиса, независимое восстановление на Mac и монитор каждые две минуты. Есть одноразовый код восстановления аккаунта. OpenStrudel получил отдельные sandbox и production ключи; production требует обычного подтверждённого платежа и не даёт доступа к другим аккаунтам.

Живой пилот Kamatera 5 октября: ровно одна VM создана, прошла SSH/root, три шаблона последовательно, reboot, экспорт/восстановление и удаление. Все 17 прежних VM сохранены. Три независимых свежих VM не создавались. Usage пилота около $0.00181, окончательный счёт ещё не подтверждён. Доказательства: `outputs/live-pilot.json`.

Живые неоплаченные счета проверены отдельно от списания денег. Для Stripe и Cryptomus подтверждены штатное истечение/отмена, настоящие подписанные события, callback HTTP 200 и освобождение резерва. Итоговый протокол — `outputs/production-readiness.json`. **Реальное списание картой, поступление криптовалюты и выплата продавцу в этой проверке не выполнялись.**

## Запуск

Для приложения нужны Node.js 24+ с `node:sqlite`, `ssh`, `ssh-keygen`, `ssh-keyscan`. Для полного набора тестов нужны `age` и настоящий `/usr/sbin/sshd`: он только разбирает временные конфигурации, демон не запускается. Docker устанавливает OpenSSH Server в тестовый этап; в конечном образе остаётся только клиент. npm-зависимостей нет.

```sh
npm start
```

Открыть http://127.0.0.1:4781. Зарегистрировать любой собственный тестовый аккаунт с паролем от 12 символов. Выбрать назначение, согласиться с условиями, перейти к оплате. На странице эмулятора есть success / cancel / fail. При success после последовательных проходов worker появится учебный IP и скачивание настоящего SSH-ключа. **Учебный IP не является VM, соединиться с ним нельзя.**

```sh
npm test
npm run check
npm run ops -- list
npm run ops -- reconcile <WAI-server-UUID>
node --env-file-if-exists=.env scripts/backup.mjs
```

Не открывайте эмулятор в интернет. Сервер проверяет loopback bind и origin; HTTP-сессии используют HttpOnly/SameSite, mutating requests требуют Origin и CSRF. Для публичного домена необходимы TLS и Secure cookie.

## Что внутри

- Node HTTP + SQLite WAL; durable users, sessions, orders, payments, servers, provisioning attempts, audit and worker lease.
- Строго один провайдер: Kamatera. REST API создания + SSH bootstrap с цифровой подписью. Native `user_data` в проверенной схеме отсутствует.
- У проверенного Ubuntu 26.04 основной `sshd_config` не включал drop-in файлы. Настройка теперь помещает управляемый блок в начало основного файла, проверяет `sshd -t/-T`, сохраняет копию и откатывается при ошибке reload. На настоящей VM подтверждено `passwordauthentication no`.
- Пароли scrypt, session tokens хранятся как SHA-256, ключи VM шифруются AES-256-GCM с привязкой к UUID. Скачивание ключа требует свежей авторизации.
- Один заказ переиспользуется при повторном клике. Один checkout на заказ. Подпись webhook проверяется по raw body, затем checkout сверяется server-to-server. Проверяются пользователь, заказ, сумма, валюта, payment mode и paid status.
- До POST создания фиксируется durable attempt. После неизвестного результата только сверка по уникальному имени. Второй POST автоматически не отправляется.
- Продление вручную по явному согласию. Отмена в конце периода. При неоплате 3 дня на экспорт и оплату, затем stop → terminate → подтверждение отсутствия. Выключенная VM продолжает тарифицироваться.
- Ручной экспорт данных приложения по SSH. Внешние автоматические backup не входят в текущий тариф. Данные WAI VDS и оба ключа ежедневно копируются и шифруются age; Mac ежечасно получает копию и проверяет восстановление. Это не backup файлов клиентской VM.
- Два режима интерфейса: «Для себя» и «Для агента». Для агентов есть `/llms.txt`, OpenAPI и отзываемые ключи на срок до30 дней. OpenStrudel получил sandbox-аккаунт на 10 учебных серверов и отдельный production-аккаунт с обычной hosted оплатой. Никаких пользовательских OpenAI токенов сервис не запрашивает.

## Переход к живой инфраструктуре

Сначала прочитайте `docs/OPERATIONS.md`. Конфигурация — `.env.example`. Секреты только на backend в файле 0600 или secret manager. У WAI уже есть документированный аккаунт Kamatera; разрешённая проверка использовала ключи из VPN-панели, не меняя её сервисы. Префикс `wai-vds-` + точный сохранённый provider UUID защищают чужие VM от операций адаптера.

Для бесплатной проверки доступа из этого чата:

```sh
node --env-file=work/kamatera.env scripts/preflight.mjs
```

Этот скрипт ничего не изменяет у провайдера и выводит текущую публичную оценку цены. Прямые ключи Stripe `sk_live_` отвергаются встроенным test-adapter: реальная оплата проходит через отдельную App WAI Pay со scope `payments:v2`, provider account `stripe-vds` и отдельным Stripe webhook.

Оператор и поддержка опубликованы в интерфейсе: WaiWai, LLC, hi@waiwai.is. Возвраты при невозможности выдачи рассматривает оператор. Окончательные налоги/счёт Kamatera, фактическое денежное зачисление и payout не выдаются за проверенные. Подробности эксплуатации и остановки новых продаж: `deployment/PRODUCTION.md`.

Runtime и секреты не отслеживаются Git. Для установленного Mac-сервиса они находятся в `~/Library/Application Support/WAI VDS/data`; `.env` указывает этот путь. Локальный launch agent `is.wai-vds.local` сохраняет доступность API после окончания чата. Dev/test runtime по умолчанию остаётся в `work/`. Не удаляйте `master.key`: без него невозможно восстановить ключи VM. Исследование и HTML не содержат credentials.
