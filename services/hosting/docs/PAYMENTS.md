## Привязка платежа

Метод, сумма и валюта сохраняются в заказе до перехода в checkout. Один заказ не меняет способ оплаты после согласия. Перед сетевым вызовом сохраняется точный запрос: внешний ID, номер поколения, account провайдера, customer email, metadata владельца и заказа. На API v2 уходит тот же `Idempotency-Key`, что и внешний ID. После неизвестного ответа выполняется поиск по сохранённому внешнему ID. Фоновая сверка никогда не создаёт новый invoice.

Карточные данные обрабатывает hosted checkout. WAI VDS не принимает номер карты, CVC, кошелёк пользователя или seed phrase. API-ключ WAI Pay и callback secret остаются на backend. Для проекта используется отдельная App со scope `payments:v2`; существующие App не изменяются.

Callback: `/api/v1/webhooks/wai-pay`. Проверяются HMAC-SHA256 исходных байтов, версия2, event ID, delivery ID, структура и payment version. Затем платёж читается по серверному API и сверяются provider/account, mode, external ID, сумма, валюта, пользователь и заказ. Выдача разрешена только при подтверждённом успешном платеже с достаточной суммой после возвратов.

Если подписанное событие опережает обновление API, backend возвращает 503 без записи receipt. Повтор безопасен. При потере callback worker вызывает штатный `sync`: WAI Pay читает upstream и обновляет свой снимок. Этот вызов не создаёт invoice, не списывает деньги и не делает возврат. Такое восстановление отдельно отмечается в audit. Ожидающие оплаты проверяются не чаще раза в 30 секунд, завершённые попытки также сверяются раз в час в течение 30 дней, чтобы обнаружить позднюю оплату или возврат с потерянным callback. Более старые события требуют операторской сверки. Если старое поколение оплачено во время создания нового checkout, клиент возвращается в кабинет без новой ссылки оплаты.

Подтверждённая неоплаченная отмена/expiration позволяет новое поколение checkout на том же заказе. Частично оплаченный crypto invoice не заменяется незаметно новым. Поздний второй платёж не создаёт вторую VM и появляется у оператора как `additional_payment_needs_refund`. Возврат/недостача до выдачи блокируют выдачу; после выдачи требуют решения оператора и не удаляют данные клиента автоматически. Реальные автоматические refunds не включены.

## Режимы и запуск

Локально остаётся бесплатный эмулятор. Прямой Stripe adapter поддерживает только test credentials. Реальные Stripe/Cryptomus работают через WAI Pay в явно заданном LIVE; API key prefix у WAI Pay одинаков для test и live, поэтому режим всегда сверяется отдельным полем. Смена режима требует другого каталога данных и не переносит тестовые agent keys.

Публичный WAI VDS размещён на существующем платёжном хосте под `/vds`, с собственным контейнером, базой, ключами и лимитами. Checkout открыт по запросу пользователя о production. Начальный предел — одна активная VM или зарезервированный оплачиваемый checkout. Место резервируется до создания счёта; неизвестный результат или незавершённая обработка сохраняют резерв. Только подтверждённая неоплаченная отмена/expiration всех попыток освобождает его. Продление уже существующей VM не занимает второй слот.

Перед checkout и непосредственно перед созданием Kamatera выполняется свежая проверка официального публичного калькулятора. После авторизации перед самым create повторно проверяются оплата, возвраты, резерв и рабочая lease. Недоступная/невалидная цена блокирует создание, старой запасной цены нет. Это оценка затрат, а не договорная котировка аккаунта или общий лимит его расходов.

На Mac и Linux/Node 24 прошли 213/213 основных тестов без пропусков. Ещё 35 проверок покрывают установку Stripe и безопасные сценарии проверки неоплаченных LIVE счетов. Миграция схемы 6→7 проверена на копии; настроены восстановление аккаунта, доверенный proxy IP, ежедневные зашифрованные копии с реальным восстановлением на Mac и мониторинг. Текущий runbook: `deployment/PRODUCTION.md`.

Для выбранного профиля аккаунт подтвердил базу $6/месяц и известную административную комиссию 2% ($6.12 до налога). После удаления тестовой VM текущий usage-отчёт показывает около $0.00181. Это не финальный invoice: налог, комиссия и округление ещё не подтверждены. Отчёт после удаления обозначил строки как Hourly, хотя активная VM показывала monthly; причина не установлена. Из этого результата нельзя выводить общее правило возврата за удалённую monthly VM.
