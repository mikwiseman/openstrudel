# Вход по ссылке через Resend

Основной вход на `https://server.waiwai.is/`: email → письмо → «Подтвердить вход». Первый подтверждённый email создаёт аккаунт; существующий возвращает владельца к его серверам. Пароль можно добавить в меню аккаунта и затем использовать как дополнительный способ. Сам экран входа не создаёт заказ и не запускает оплату.

Отправитель: `WAI Server <login@mail.waiwai.is>`. Домен `mail.waiwai.is` подтверждён в Resend; sending enabled, click/open tracking выключены. Для OpenStrudel меняются тема и содержание письма, отправитель остаётся тем же. Секрет находится только в root-owned `/srv/wai-vds/runtime.env` (0600), окружении backend и зашифрованных резервных копиях. Его нет в исходниках, JavaScript, документации и HTML письма.

## Поведение

- Ссылка действует 10 минут; для OpenStrudel срок ограничен также исходной авторизацией. Успешный вход использует её один раз.
- Ссылка открывается в **том же браузере**, где запрошена. Другой браузер/устройство не получает доступ и не расходует ссылку. Нужно вернуться в исходный браузер или начать вход заново. В OpenStrudel повторный вход запускают из приложения.
- GET, предпросмотр почты и проверка ссылки ничего не подтверждают. Нужен явный POST после кнопки. Секрет находится во fragment и удаляется из адресной строки до запроса; в серверные URL/access logs он не попадает.
- HttpOnly, SameSite=Lax, Secure и `__Host-` защищают cookie запроса в production. Сама сессия HttpOnly/Secure/SameSite=Strict. CSRF и точный Origin проверяются на изменяющих запросах.
- Токены и cookie запроса сохраняются в SQLite только как SHA256. Реальный текст письма хранится у Resend как у выбранного почтового провайдера. Никакие SSH/root, OpenAI или платёжные секреты в письме не отправляются.
- Ответ запроса одинаков для существующего и нового email. Лимиты: 1 письмо/минуту и 5/час на email, 20/час на IP, 100/час и 1000/сутки на сервис. Счётчики переживают перезапуск. Истёкшие заявки удаляются при следующем запросе через сутки.
- Каждый вызов Resend получает свой Idempotency-Key. Неизвестный результат отправки сохраняется как unknown; повторной отправки вслепую нет. Если письмо всё же доставлено, его ссылка работает до истечения срока. При окончательном отказе ссылка недействительна.

## Защита ранее неподтверждённого email

Первое подтверждение адреса отключает прежний **неподтверждённый** пароль, коды восстановления, сеансы и API/native grants этого аккаунта. Заказы, серверы и файлы сохраняются. Это закрывает захват через предварительную регистрацию чужого email. Пароль, установленный владельцем после подтверждения почты, последующие входы по ссылке не отключают. Скачанные SSH-ключи не ротируются автоматически.

Подтверждение по письму действительно для чувствительных действий пять минут. Для SSH, API-ключа, удаления и нового recovery code интерфейс умеет отправить письмо повторного подтверждения. Оно привязано к конкретной текущей сессии, не может переключить владельца или освежить другой браузер. После письма пользователь возвращается на исходную вкладку и повторяет выбранное действие. Создание/смена пароля требует свежего подтверждения именно по почте. Восстановление сохранённым recovery code инвалидирует ожидающие email-ссылки и старые сеансы.

## OpenStrudel

Нативный контракт не меняется: public client + authorization code + PKCE S256. Старт из `/oauth/authorize` показывает бренд OpenStrudel и вход по email. Запрос письма связан с исходной авторизацией и её браузерным nonce. Подтверждение сохраняет тот же redirect allowlist, state, issuer и PKCE challenge; отмена/истечение исходной авторизации прекращают вход. Приложение получает только короткоживущий authorization code, затем самостоятельно обменивает его с verifier. Общего ключа в приложении нет. Отдельного кабинета WAI VDS в этом сценарии нет.

## Внутренние браузерные endpoints

Это endpoints сайта, не замена нативному OAuth API. JSON, no-store. Все POST требуют точный Origin сервиса и Content-Type application/json.

| Endpoint | Тело / результат |
|---|---|
| GET `/api/v1/auth/options` | `magic_link`, `password`, `magic_fresh_until`, `password_enabled` |
| POST `/api/v1/auth/magic-link/request` | `{email, context: "login", return_view: "new" \| "servers" \| "agent"}` → 202 `{ok, expires_in, retry_after}`; ставит browser cookie |
| POST `/api/v1/auth/magic-link/request` | `{context: "reauth"}` + сессия/CSRF; email берётся только из аккаунта |
| POST `/oauth/magic-link/request` | `{email, context: "oauth"}` + исходная cookie авторизации |
| GET `/auth/email` | Экран подтверждения; секрет только во fragment, GET его не использует |
| POST `/oauth/magic-link/inspect` | `{token}` + browser cookie; `{email, context, brand}` без изменения входа |
| POST `/oauth/magic-link/consume` | `{token}` + browser cookie; новая HttpOnly сессия или reauth текущей; `{user, csrf, redirect_uri, context, first_verification}`. Сессионного bearer в JSON нет |
| POST `/api/v1/auth/password` | `{password}` + session/CSRF и свежее email-подтверждение; `{ok:true}` |

Неверная/использованная/истёкшая ссылка: 400. Чужой/потерянный браузерный контекст: 409. Чужой Origin или отсутствие CSRF: 403. Ограничение попыток: 429. Отправка не подтверждена: 503. Нельзя передать произвольный return URL.

## Выпуск и восстановление

Схема 8→9 добавляет `magic_links`, `magic_sessions`, `email_verifications`; старые строки не переписываются. `scripts/check-migration.mjs` проверяет независимый snapshot и все прежние колонки/строки. `deployment/magic-upgrade.py` предназначен для v10→v11 и финальной доработки v11→v12 на документированном хосте: inspect, Linux suite, timestamped backup, rehearsal, atomic env apply, exact-service recreation, HTTPS/health/catalog checks; при отказе код/конфигурация возвращаются к предыдущему выпуску, текущая база сохраняется. Caddy, WAI Pay, цены и инфраструктурные ограничения не меняются.

Для отключения отправки задайте `WAI_MAGIC_LINK_ENABLED=0` и примените конфигурацию тем же безопасным процессом. Сайт покажет парольный вход. Уже созданные passwordless аккаунты требуют возврата исправленного email-входа либо сохранённого recovery code; не объявляйте fallback полным восстановлением всех аккаунтов. Ожидающие ранее выданные ссылки действуют до TTL, если явно не отозваны оператором.

## Проверки

Автотесты используют локальный mailer и покрывают replay/TTL, другой браузер, scanner GET/inspect, origin/CSRF, отсутствие произвольного redirect, rate limits после рестарта, pre-hijack, сохранение подтверждённого пароля, step-up, восстановление, неизвестную отправку и PKCE/отмену.

`scripts/magic-live-proof.mjs --run-free-proof` разрешено запускать только на этом production-хосте. Он использует специальные `delivered+…@resend.dev` адреса, проверяет настоящий Resend API и настоящий web/OAuth вход, затем выходит и отзывает native grant. Это **эмуляция доставки Resend**, не доказательство попадания в личный inbox человека. Никаких VM, оплат и счетов. Сырые письма/ссылки/cookies остаются только в памяти; evidence содержит только результаты.
