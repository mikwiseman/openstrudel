# OpenStrudel — ревизия устройств, сотрудников и основных сценариев

7 октября 2026. Реализация: `codex/device-first-redesign`.

Изменения находятся в рабочей ветке и отдельной сборке **OpenStrudel QA**. Установленное приложение и его рабочие сотрудники не заменялись. Это проверенная переработка основных сценариев; полный выпуск для всех устройств пока не принят — ограничения перечислены ниже.

## Модель продукта

Сотрудник работает на конкретном устройстве. Его история, файлы, расписания, аккаунты и доступ к сервисам остаются там же. Приложение на Mac или iPhone подключается к нескольким таким устройствам независимо. Выбор сотрудника переключает соединение; общего обязательного управляющего устройства нет.

На Mac создание начинается с задачи сотрудника. Текущий Mac выбран по умолчанию; при наличии других подключений можно выбрать другое устройство до отправки. Текст и вложения переходят вместе с этим выбором. Образ меняется в настройках сотрудника. Обязательные «Личное / Работа» и действие перемещения из обычных настроек убраны.

Исторический протокол primary/executor оставлен для совместимости с существующими установками и незавершёнными операциями. Новые независимые подключения не используют его для объединения устройств. Автоматической миграции старого кластера в новую топологию в этой работе нет. Веб-интерфейс остаётся интерфейсом одного устройства; несколько независимых устройств объединяет нативное приложение.

## Что изменено

| Сценарий | Новое поведение |
| --- | --- |
| Устройства | Независимые соединения, отдельные учётные данные, каталоги, состояния и запросы. Недоступное устройство не блокирует остальные. Компактный список; подробности раскрываются только для выбранного устройства. |
| Навигация | Сотрудники сгруппированы по устройствам. Вместо категорий назначения показано реальное место работы. |
| Создание | Задача → устройство при необходимости → отправка. Выбор образа перенесён в настройки. При смене устройства не остаётся второй пустой сотрудник. |
| Подключение | Получить ссылку на устройстве с сотрудниками → вставить или отсканировать на другом → подтвердить название → увидеть результат → открыть сотрудников. JSON и каталог управляющих доступов скрыты из повседневного сценария. |

| Потеря входа | История и черновик сохраняются; отправка недоступна до восстановления. Кнопка входа открывает аккаунты нужного устройства. Ошибка сети не выдаётся за необходимость нового входа. |
| Сервисы | Ограниченное ожидание каталогов, сохранение списка уже доступных приложений при сбое общего каталога. Подключение показывает начало, ожидание браузера, ошибку и проверенный результат. |
| Telegram | Создание бота через BotFather → проверка ключа → личная ссылка → «Начать» → подтверждённое подключение чата. Этот путь доступен из настроек сотрудника. |
| Копии | Один файл с сотрудниками, перепиской, файлами и расписаниями. Защита паролем — понятный необязательный переключатель. Доступы к OpenAI и сервисам не экспортируются. |
| Прогресс | Подготовка без выдуманного процента; получение — по фактическим байтам и Content-Length. Доступна отмена. После сохранения показаны файл и папка; на Mac есть переход в Finder. |
| Восстановление | Проверка пароля и содержимого до записи, предварительный просмотр, добавление без замены текущих сотрудников. Повторный импорт не создаёт дубликатов; расписания восстанавливаются на паузе. |
| Выход | «Убрать подключение» объясняет, что сотрудники остаются на устройстве. Необязательная копия — отдельное действие. Ожидание отзыва удалённого доступа ограничено пятью секундами. |
| Доступность | Системный шрифт, контрастные состояния, подписи действий. При максимальном размере текста кнопки растут по содержимому; поле ввода оставляет место истории. |

## Найденные и исправленные дефекты

- Падение при запуске: объект соединения был недоступен модификатору пункта меню.
- Падение системного сохранения: `FileWrapper.preferredFilename` получал `nil`.
- Медленная большая копия: обработка каждого байта выполнялась на потоке интерфейса. Сбор данных перенесён за пределы MainActor; обновления прогресса поступают порциями.
- Дубликат черновика сотрудника после выбора другого устройства.
- Кнопка отправки оставалась доступной после истечения входа OpenAI.
- Кнопка восстановления входа открывала список устройств вместо аккаунтов.
- Устройство с правами владельца не показывало создание ссылки из-за невыполнившегося `.task` у пустого `Group` и несовпадения формата статуса подключений.
- Генерировалась ссылка без нужного признака владельца для подключения собственного устройства.
- При недоступном общем каталоге сервисов терялись уже подключённые приложения.
- Даже успешный UI-тест не заметил наложение текста кнопки при максимальном Dynamic Type. Дефект обнаружен на скриншоте, исправлен и проверен повторно.
- После защищённого экспорта веб-интерфейс сбрасывал переключатель и показывал «Файл без пароля». Теперь состояние и подтверждение однозначно говорят о защищённой копии; сам пароль очищается.
- Повторяющиеся инструкции для каждого устройства вытесняли основную кнопку за пределы окна. Три устройства и кнопка подключения теперь видны вместе; инструкции раскрываются по нажатию.
- Общий помощник OpenStrudel пропадал из результатов поиска на Mac. Поиск теперь охватывает его и сотрудников всех подключённых устройств; на iPhone возвращено явное состояние пустого результата.
- В мобильном подключении оставались старые формулировки о приглашении в команду. Ввод, QR, срок действия и справка теперь последовательно говорят о ссылке подключения устройства.

## Проверки с реальным интерфейсом

Стенд: отдельное приложение `is.openstrudel.revision-qa`, три независимых runtime с отдельными SQLite, каталогами и TLS-сертификатами на этом Mac. Названия QA Mac, QA Mini и QA VDS обозначают стендовые процессы, а не физические машины. Ответы сотрудников и остатки на этом стенде заданы тестовыми реализациями. Сетевой протокол, базы, клиент, сохранение и восстановление настоящие.

| Проверка | Результат и граница доказательства |
| --- | --- |
| Локальный сотрудник | Создание и отправка через нативный UI; ответ приходит от локального тестового runtime. |
| Несколько устройств | Подключены два дополнительных независимых runtime. Все три видны в одном списке; подключения сохраняются после перезапуска. |

## Автоматические проверки

- TypeScript: `npm run typecheck` и `npm run build` прошли.
- Runtime: **231 тест, 38 файлов**, полный запуск Vitest прошёл с `--maxWorkers=4 --testTimeout=15000`. Повышен только лимит командного запуска: существующий тест установщика с несколькими процессами превышал стандартные 5 секунд на загруженном Mac.
- Нативные тесты: **94 теста, 13 наборов**, macOS `xcodebuild test` прошёл.
- iOS: **9 сценариев** в настоящем симуляторе со сборкой приложения: два `AccountRecoveryUITests`, `DesignAccessibilityUITests/testMainScreens`, `ReleaseScenariosUITests/testSettingsEmployeesMessagesAndRecovery`, пять `MobilePairingUITests`. Повторные проверки основных экранов и первого подключения выполнялись на очищенном тестовом симуляторе с новыми изолированными серверами.

Стендовые файлы, журналы и скриншоты находятся локально в [каталоге проверки](../.data/revision-2026-10-07/). Они не входят в Git: в отдельных журналах могут находиться уже использованные одноразовые тестовые ссылки. Ключ Telegram в исходники и этот отчёт не включён.

## Границы проверки перед выпуском

1. Физические Mac Mini/VDS через LAN/WAN не проверены. `waiMini.local` в текущей сети не разрешается. Три независимых TLS runtime на одном Mac доказывают маршрутизацию и изоляцию клиента, но не работу NAT, внешних адресов и реальной сети.
2. Установка полного macOS-пакета на чистую ОС и первый вход реального нового пользователя не пройдены. Установщик покрыт тестами; используемая QA-сборка не заменяет установленное приложение и его LaunchAgent.
3. Новый OAuth-доступ к Google с пустого аккаунта не выдавался. Проверен реальный вызов уже подключённого Calendar; остальные сервисы не считаются проверенными по одному успешному вызову.
4. Проверки iOS выполнены в симуляторах. Физический iPhone/iPad и все сочетания размеров окон, тем, VoiceOver и масштаба текста ещё требуют приёмки.
5. Исторические кластеры primary/executor сохраняют протокол совместимости; автоматическое преобразование их топологии не реализовано. Нужна отдельная приёмка существующей рабочей установки до массового обновления.
6. Подпись для распространения, notarization, TestFlight, публикация и платное создание серверов в этой работе не выполнялись.
