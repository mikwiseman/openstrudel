# Build 66 — Mac and Home runtime update

Prepared from runtime source `eda94af`. This record describes the release
candidate; publication and production installation are separate acceptance steps.
At preparation, the public Mac feed still advertises build 63 and this Mac mini
has build 49 installed.

## Changes

- The bundled Home includes access-scoped owner source discovery, streamed
  imported history, and the incident lifecycle fixes already tested on the
  current runtime. An unrelated successful turn cannot clear another task's
  failure; task, transcription and delivery recovery remain independent.
- The previously production-only document-signing implementation is now
  reproducible from committed typed source, with its owner, channel, scheduling,
  binding and path checks preserved. This is reconstructed source, not a claim
  that the missing original commit was recovered.
- The Mac build number advances to 66. Native application sources are unchanged
  since build 65. XcodeGen regenerated the project; build inputs and file
  references are unchanged apart from version metadata and generated identifiers.
- A test-only URL protocol explicitly captures its already-Sendable instance in
  its task, as required by Xcode 26.6. No production native UI behavior changed.

## Candidate verification

- Native Mac tests: 350 passed, 10 skipped, zero failures. Skips require real
  remote hosts or audio fixtures and do not establish that acceptance.
- Signed bundle: all five packaged-runtime and installer checks passed, including
  bundled Node, SQLite, crypto, launch-agent generation, Claude JIT and Grok.
- Home, cloud and server installer checks: 61 passed with one worker.
- Release is arm64 with a retained matching dSYM. The app and DMG are Developer
  ID signed, accepted by Apple, stapled, and accepted by Gatekeeper.
- The pinned Sparkle tools generated a one-release feed and independently
  verified its signature, the DMG signature, enclosure URL and byte length.
- An isolated copy of the actual installed build 49 is prepared to exercise
  discovery, download, installation and relaunch to 66. Its distinct bundle ID,
  signed-out state, fake Home endpoint and removed runtime preserve the personal
  Home. The app requires HTTPS; the first loopback HTTP fixture was correctly
  rejected before update discovery. Interactive acceptance subsequently passed
  through the signed HTTPS fixture: 49 discovered 66, downloaded it, offered
  Install and Relaunch, reopened as 1.0 (66), and reported itself up to date on
  a second check. The test app was then quit; it never connected to a Home.

## Publication gates

The production feed and installed application were not changed during candidate
preparation. Publish immutable artifacts first, verify their external hashes,
then atomically update the feed, stable aliases and checksums with rollback.
Keep release archives and dSYM on the release Mac.

Current AGENTS instructions require only the latest installers on WaiWeb. The
older runbook's previous-Home exception must not silently override that policy.
DigitalOcean refreshes the quote and release immediately before creation, but a
server already being created retains its original archive. Such pending installs
have no central expiry that can be inferred from a quote. Check available live
evidence before deleting old archives and report any unresolved in-flight case.
