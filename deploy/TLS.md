# HTTPS на собственном главном устройстве

Веб-интерфейс обслуживает само главное устройство. Для браузера нужен сертификат, которому доверяет ОС. Mac/iOS/CLI также проверяют идентичность Home по открытому ключу из приглашения. Продление с тем же ключом не требует повторного подключения.

Эта инструкция и hook прошли локальную проверку с тестовыми сертификатами. Выдача и автоматическое продление настоящего сертификата CA на независимом Linux-сервере ещё не приняты. Это условие выпуска публичного веба.

## Подготовка до первого приглашения

На выделенном сервере: установленные Docker/Compose, Node 22.5+, Certbot 5.4+, публичный IPv4 или собственный домен, доступный TCP 80 для проверки владения адресом и порт Home (по умолчанию 7789). Сначала проверьте, что порт 80 свободен. Не останавливайте чужой веб-сервер ради этой инструкции; для занятого порта используйте существующий webroot по документации Certbot.

Получите сертификат интерактивно; владелец сам подтверждает условия CA. Пример для своего домена:

```sh
sudo certbot certonly --standalone --cert-name openstrudel-home --reuse-key -d home.example.org
```

Для публичного IP вместо `-d` применяются `--ip-address ВАШ_IP --required-profile shortlived`. Короткоживущий сертификат требует исправного автоматического продления. Не подставляйте пример IP в рабочую конфигурацию.

Подготовьте отдельную копию сертификата для непривилегированного контейнера. Закрытый ключ не попадает в образ или Git:

```sh
sudo env RENEWED_LINEAGE=/etc/letsencrypt/live/openstrudel-home \
  OPENSTRUDEL_TLS_DIRECTORY=/opt/openstrudel/deploy/tls \
  OPENSTRUDEL_PUBLIC_HOST=home.example.org \
  node /opt/openstrudel/deploy/tls-install.mjs --prepare
```

Каталог установки может отличаться от `/opt/openstrudel`. Укажите фактический путь. По умолчанию файлы принадлежат root, группе 1000 и имеют права 0640; это соответствует пользователю контейнера из `compose.yaml`. Для другой установки задайте точные `OPENSTRUDEL_TLS_UID/GID`.

После проверки конфигурации включите overlay для **этой** установки:

```sh
docker compose -f compose.yaml -f compose.tls.yaml config --quiet
docker compose -f compose.yaml -f compose.tls.yaml up -d home
```

Проверьте HTTPS без `-k`, откройте страницу с другого устройства, затем выдавайте приглашения. Первое включение overlay меняет конфигурацию и перезапускает только Home. Обычное продление перезапуска не требует.

**Уже подключённый Home с самоподписанным сертификатом:** новый ключ CA изменит идентичность. Не выполняйте этот переход как незаметное обновление. Сохраните копию и организуйте повторное подключение клиентов либо отдельную процедуру сохранения прежнего ключа. Hook намеренно не умеет обходить эту проверку.

## Продление

Существующий таймер Certbot должен оставаться единственным расписанием продления. Не создавайте второй cron/timer. В его deploy hook для lineage `openstrudel-home` передайте те же переменные и выполните `tls-install.mjs` **без** `--prepare`. В настройке сертификата сохраните `reuse_key = True`.

Hook проверяет срок, SAN, пару сертификат/ключ и прежний открытый ключ, записывает новую защищённую версию, атомарно меняет `current` и проверяет фактически выдаваемый TLS-сертификат. Home перечитывает сертификат раз в минуту. При неудаче hook возвращает прежние файлы, проверяет выдачу прежнего сертификата и возвращает ненулевой код; предыдущие версии остаются в `generations/`. Проверьте журнал и действующий сертификат перед повтором. Никакой bearer-токен в TLS-проверке не используется.

Перед выпуском обязательны: штатное продление, потеря сети у CA, неверная пара ключей, истёкший сертификат, перезагрузка сервера, сохранение прежнего приглашения после продления. `certbot renew --dry-run` проверяет staging CA и по умолчанию не запускает deploy hook; это отдельная проверка, а не доказательство работы полного пути.

Источники: [Certbot: выдача, reuse-key, IP и deploy hooks](https://eff-certbot.readthedocs.io/en/stable/using.html), [Let's Encrypt: IP-сертификаты](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability/).
