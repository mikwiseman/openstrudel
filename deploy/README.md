# OpenStrudel 1.0 — личный сервер

Комплект для администратора собственного VDS. Установщик настраивает и запускает уже арендованный сервер; он не создаёт аккаунт у хостинга. Для установки без терминала выберите облачный запуск в приложении Mac или iPhone: войдите в свой аккаунт DigitalOcean, проверьте цену и подтвердите создание сервера. DigitalOcean — единственный встроенный облачный провайдер, оплата идёт напрямую ему. Чтобы прекратить начисления, сохраните нужные данные и удалите сервер в DigitalOcean; выключения сервера недостаточно.

Нужны Ubuntu 22.04, 24.04 или 26.04 с AppArmor, Docker Engine 29+ с Compose, публичный адрес и открытый TCP-порт 7789. Начальная конфигурация: 2 vCPU, 4 ГБ памяти и 20 ГБ диска. GPU не нужен. Проверено на Ubuntu 26.04 с Docker 29; другие контейнерные хостинги отдельно не проверены.

## Установка

Распакуйте комплект, перейдите в его папку и выполните:

```sh
bash scripts/install-server.sh
```

Установщик проверит среду, определит публичный IPv4, загрузит профиль AppArmor, запустит Compose и выдаст личное приглашение. Повторный запуск сохраняет `deploy/.env`, том данных и подключённые устройства; вы получите новое приглашение. Он не меняет firewall, SSH, настройки ядра или чужие контейнеры.

Если Docker ещё не установлен, выполните [официальную инструкцию Docker для Ubuntu](https://docs.docker.com/engine/install/ubuntu/) и повторите команду. Сам установщик не устанавливает и не обновляет системные службы.

Если сервер использует домен или находится за NAT:

```sh
bash scripts/install-server.sh --host your-server.example.com
```

Можно задать `--port 7789`. Для отдельной установки на том же сервере нужны свои `--dir`, `--project` и `--port`. Если переданные параметры отличаются от уже сохранённых, установщик останавливается; адрес подключённых устройств не меняется незаметно.

Самостоятельный установщик также умеет скачивать официальный архив по HTTPS с проверкой опубликованной SHA-256. Он не распаковывает ссылки, пути за пределами архива или пользовательские данные. Для установки из готового комплекта скачивание не требуется.

## Ручная настройка

При необходимости можно выполнить те же действия самостоятельно. Создайте `deploy/.env`:

```dotenv
OPENSTRUDEL_PUBLIC_HOST=your-server.example.com
OPENSTRUDEL_PUBLIC_PORT=7789
TZ=Europe/Moscow
```

Укажите действительный публичный домен или IPv4 вашего сервера. Затем:

```sh
sudo apparmor_parser -r deploy/docker/openstrudel.apparmor
docker compose --project-directory deploy -f deploy/compose.yaml up -d --build
docker compose --project-directory deploy -f deploy/compose.yaml logs --tail 15
```

При запуске сервер проверяет настоящий sandbox Codex: рабочая папка должна читаться, а закрытый файл вне неё — нет. Ошибку этой проверки нельзя исправлять отключением sandbox. Профили и их происхождение описаны в `deploy/docker/README.md`.

## Подключение

```sh
docker compose --project-directory deploy -f deploy/compose.yaml exec home node /opt/openstrudel/dist/cli.js pair
```

Откройте выданную личную ссылку на Mac или iPhone с OpenStrudel либо вставьте её в приложение. Она действует пять минут и используется один раз. Для следующего устройства создайте новую. Не публикуйте приглашение: оно даёт доступ к вашей установке.

Приложение предложит официальный вход в OpenAI. Пароль вводится только на странице OpenAI; API-ключ не нужен. После этого можно создавать сотрудников, писать им и подключать Telegram в настройках.

## Данные и обновления

Данные, авторизация и сертификат находятся в именованном томе `openstrudel_data` (либо `<имя-проекта>_data`, если использован `--project`). Остановка или пересоздание контейнера их не удаляет. **Не выполняйте `down -v`**, если хотите сохранить данные. Перед обновлением остановите контейнер и сделайте резервную копию тома. Повторный запуск установщика использует существующие исходники; обновление версии выполняется отдельно. Никогда не подменяйте том чужим `.codex` или личными данными другого пользователя.

Одна установка рассчитана на одного владельца. Codex работает непривилегированным пользователем, с отдельными рабочими областями и обычными запросами подтверждения. Доступ ко всему Docker-хосту и Docker socket ему не предоставляется. Для изоляции разных владельцев используйте отдельные VM.
